Why does Oracle DRCP work?

Traditional Pooling

Catalog poolInventory poolOrders poolPayments poolCustomers pool
Each service reserves DEDICATED database sessions
Oracle Database
many idle dedicated sessions

Oracle DRCP

CatalogInventoryOrdersPaymentsCustomers
Services borrow reusable resident servers
Database Resident Connection Pool
shared reusable server processes
Connection Classes

Each service requests its own DRCP connection class, so reuse is organized without duplicating a resident pool per service.

Session Tagging

Tags describe reusable state such as service, region, and role. Matching tags reduce unnecessary setup on checkout.

Session Purity

POOLED favors reuse. NEW asks for cleaner state when stricter isolation is required.

Session Fix-up

The backend sets module, action, client identifier, and connection tag after checkout so Oracle evidence remains attributable.

Shared Resident Servers

DRCP server processes live in the database tier and are reused across service requests instead of being reserved by each client pool.

Idle Session Waste

Traditional pool minimums multiply by service count. DRCP keeps the reusable capacity in one shared place.
