Runtime Path
  1. The browser calls the Node backend only; it never generates database load directly.
  2. The backend routes service requests through backend/src/services.js.
  3. DB_DRIVER=oracledb uses Oracle Client Thick mode with the user's Autonomous Database wallet directory.
  4. Traditional mode connects through DEMO_CONNECT_STRING=YOUR_ADB_TP_ALIAS and creates normal client-side pools with min=5 and max=8 per service.
  5. DRCP mode connects through DEMO_DRCP_CONNECT_STRING=YOUR_ADB_TP_POOLED_ALIAS, whose TNS entry includes SERVER=POOLED; client pools use min=0 while the shared resident pool is documented as min=2 and max=8.
  6. The mode is fixed at process startup. The UI reads it from the backend and never switches datasource configuration from the browser.
  7. ORDS exposes read-only dashboard evidence from Oracle monitoring views. Node proxies those endpoints so the browser avoids CORS and credentials.
  8. The load path still uses Node plus Oracle Net to show DRCP behavior directly; ORDS is not used to generate service workload.
DRCP Features Represented
  • Connection classes: one per service in config/services.json.
  • Session tags: service, region, and role tags generated by the load engine.
  • Session purity: UI switch for POOLED and NEW request behavior.
  • Session fix-up: after checkout, the backend sets module, action, client identifier, and the connection tag.
  • Monitoring: backend/src/db/monitoring.js consumes ORDS endpoints from ORDS_METRICS_BASE_URL. SQLcl/JDBC admin access is only a fallback path.
